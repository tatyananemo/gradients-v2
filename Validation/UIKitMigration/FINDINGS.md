## Полный SwiftUI-эталон

Сохранены 88 настоящих полноэкранных PNG, 1170×2532, 390×844 pt, 3×, iOS 18.6:

- четыре темы, 0/30/60/80/100%, отдельные MAIN и CONTACT — 40 кадров;
- дополнительные фазы CONTACT 1.2/2.1 на 30/60/80% — 24 кадра;
- свайп, удержание, три состояния отпускания и результат reset — 24 кадра.

Используется реальный SwiftUI View со всеми масками, blur, blending, подложкой,
текстом и контролами. Снимки получены из Simulator compositor через simctl, не
из offscreen Metal, ImageRenderer или нарисованных макетов.

В генерируемой тестовой копии подставляются часы и состояние. Состояния свайпа
получены исходными обработчиками, извлечёнными существующим Validation. Для
фиксированных состояний реальная GPU-проба и исходный CPU-фильтр подложки
выполняются 90 раз с шагом 1/60; затем измеренная активация замораживается для
обоих renderer. MAIN подавляет idle CONTACT через существующее условие активности
касания, без следа. Это изоляция MAIN в стенде, не новый production-маршрут.

Все хэши PNG и исходников закреплены в baseline.json. Новый захват в каталог
зафиксированного эталона запрещён скриптом. Повторная серия из 12 состояний:
11 кадров совпали полностью; один отличается максимум на 1/255, при одинаковых
uniforms, history, геометрии, времени и активации. После добавления прототипа
результат повторной проверки тот же. Такая вариативность эталона зафиксирована,
но не превращена в автоматически разрешённый допуск для UIKit.

Пределы: это фиксированные состояния, а не запись реальной доставки UITouch,
не оценка FPS, не точный эталон перехода numericText при reset и не временная
последовательность адаптивной подложки. Reset проверен по конечному состоянию;
алгоритмы прогресса, release и idle — дополнительно исходным behavior replay.

## Что реализовано в изолированном прототипе

PrototypeController — UIKit + MTKView; UIKit-композиция не содержит SwiftUI view.
SwiftUI перед native capture используется только для измерения исходной геометрии
и uniforms, после чего hosting controller удаляется. Это фиксированный стенд,
не адаптивный SDK-компонент и не перенос приложения/жестов.

Порядок: исходный фон → исходная distortion → Dark-подложка → центральные маски
→ текст/контролы. Для Light подложка — CAGradientLayer над фоном и под текстом;
центральных тёмных масок в Light нет. Dark-подложка остаётся постоянной, как в V2.
Радиусы, цвета и порядок трёх масок сохранены: blur → Yellow exclusion →
normal/multiply/screen. Все исходные восемь Metal-модулей, CONTACT, SUBSTRATE FIX,
28 uniforms, interaction history и компиляторный fast-math setting сохранены.

Новые Metal-функции — адаптеры исполнения/семплирования и UI-композитор.
Они не добавлены в baseline default.metallib: библиотека прототипа отдельная.

Подтверждённые ошибки адаптера исправлены, без подгонки эталона:

1. CGContext/CI → Metal переворачивал маски по Y. Отдельный реальный GPU-тест
   показал: заданный центр 200 сверху попадал на 644; после однократного flip —
   199.9994. Исправлено преобразование изображения, не геометрия V2.
2. Принудительный Dark UI style для материала кнопок не соответствовал исходной
   V2, где root style наследуется от системы. В прототипе восстановлено наследование.
3. Dark-подложка была над уже уплощёнными масками. Её композиция перенесена перед
   масками. Light сохраняет нативный CAGradientLayer с исходными 17 stops.

Первоначальные варианты сохранены локально в Results/experiments.

## GPU: точное сравнение без квантования

Apple M3 Pro, 390×844, RGBA16Float, исходные 72 состояния, тот же fast-math setting.
Исходные raw-хэши проверяются до запуска кандидата. Детали — gpu-results.json.

| Проверка | Побайтовое совпадение | Остаточные отличия |
|---|---:|---|
| Исходные функции в unchanged compute control | 216/216 | Нет: кадры, probe, distortion |
| Новый fragment-адаптер | 68/72 | Четыре кадра, 1–2 компонента на кадр; максимум 0.0001220703125 |
| Новый compute-first адаптер, использован в прототипе | 71/72 | Blue Dark 60%, CONTACT t2.1: один компонент, delta 0.00006103515625 |
| Эксперимент со специализацией масштаба | 2/72 | Отклонён; ухудшил численный результат |

Формулы тем не менялись. Различия возникают при смене точки входа/контекста
компиляции и адаптации координат; какая конкретно инструкция компилятора даёт
остаточный компонент, не установлено. Не вводились rounding, half-оптимизации,
изменение fast-math или допуск, чтобы объявить тест пройденным.

## Полные кадры и прозрачность

Сохранены 88 полных UIKit PNG, пары фона/distortion и фона/подложки — по 16,
Debug/Release и повторы. Входы и геометрия каждой пары проверяются на точное
равенство, ICC-профили также совпадают. Разностные PNG усилены ×8 только для
просмотра; численные метрики рассчитаны по исходным decoded RGB без допуска.
Полный список — Results/comparison.json, обзор — Results/index.html.

| Серия | Полностью одинаковые кадры | Максимальная разница канала |
|---|---:|---:|
| SwiftUI / UIKit, полный экран | 0/88 | 250/255, в области текста |
| Только фон + distortion | 0/16 | 2/255 |
| Фон + подложка | 0/16 | 2/255 |
| Debug / Release native | 11/12 | 18/255, первый Blue Dark кадр, нижний текст |
| Повтор этого Release-сценария | 3/3 | 0 |

Средняя по кадрам абсолютная разница полного экрана — около 0.323 уровня из 255.
Это описание измерения, не критерий приёмки. Крупные локальные разности на краях
глифов не скрыты этим средним.

Что пока не совпадает:

- Конечный вывод фона: исходные цвета/параметры те же, но цепочка sampling,
  форматов текстур и вывода SwiftUI/MTKView не идентична. Остаток измерен;
  точная доля координатного и цветового округления не установлена.
- Маски/blur/blending: исходные параметры и логический порядок воспроизведены,
  но CG-маска начинается с 8-bit premultiplied raster, далее идёт CI Gaussian и
  RGBA16Float-композиция. Нет доказательства идентичности этого пути внутренним
  precision, blur kernel, gradient interpolation и compositing space SwiftUI.
- Текст, тени процентов и контуры/материалы контролов: нативные UILabel,
  CALayer и UIVisualEffectView не дали pixel-identical растеризацию SwiftUI.
  Измерение тех же bounds и использование тех же размеров/весов шрифта этого
  не гарантируют. Нижней подписи тень/обводка не добавлялись.
- Первый native Release-кадр: отличается только подпись, 6223 пикселя, max delta18.
  Повтор того же состояния и ещё двух фаз совпадает с Debug. Это указывает на
  зависимость от первого показа/растеризации, а не постоянное различие палитры;
  точная причина пока не установлена. Ранний опыт с delta22 сохранён отдельно.

Прозрачность проверена по исходным alpha/stops и итоговой композиции. Полного
побайтового эталона внутренних SwiftUI mask/blur textures сейчас нет. Считать
их alpha и blending идентичными по одному сходству скриншотов нельзя.

## Сборки и неизменность

- Xcode 26.3. Исходная V2: Debug и Release Simulator build — успешно.
- Изолированный стенд: Debug и Release — успешно; все четыре темы реально показаны.
- Существующий Validation: 72 кадра, 216 raw GPU outputs, 33 behavior checkpoints —
  пройдены; исходный reference.json не перезаписывался.
- Исходники/проект V2 в рабочей копии неизменны: Swift 1036, Metal 10165,
  активный application source всего 11201 строк. Стенд не включён в app target.
- Хэши защищённых проектов: original V2 15/15, production 9/9, V3 15/15 — совпали.
- Отдельный bundle ID стенда: com.local.gradients.v2.migrationprobe, только в
  изолированном Simulator Gradients V2 Refactor Validation. Исходные приложения
  не устанавливались поверх и не удалялись. GitHub не использовался.

## Что необходимо решить перед продолжением

1. Добиться точного GPU результата новой точки входа на всех 72 состояниях,
   сохраняя исходные формулы и компиляторный режим.
2. Установить исходные форматы/цветовое пространство и blur/blend semantics
   SwiftUI, затем проверить нативную реализацию по отдельным промежуточным слоям.
3. В отдельном UI-этапе воспроизвести baseline/line layout текста, тени процентов,
   материалы и stroke контролов, а также устранить нестабильность первого кадра.
4. До миграции анимаций расширить full-screen baseline переходами подложки,
   numericText/reset и реальной последовательностью событий OS.

На этих двух этапах работа остановлена. Удаления SwiftUI, SDK API, упаковки,
переноса механики свайпов и внедрения в V2/production не выполнено.
